# DickCraftTg

Telegram-игра для групп на Python 3.10+. На Windows дополнительно установите базу часовых поясов: `py -m pip install tzdata`. На Linux обычно используется системная база часовых поясов.

## Запуск

1. Создайте бота в @BotFather. Сохраните токен в защищённой переменной окружения `BOT_TOKEN`, не в Git и не в чате.
2. Укажите `OWNER_ID` — положительный числовой Telegram ID вашего личного аккаунта (не username и не ID группы). Эта настройка обязательна; без неё бот не запустится. Откройте личный чат с ботом и отправьте `/start`, затем `/admin`, для просмотра заявок.
3. В @BotFather выполните `/setprivacy` → выберите бота → Disable. Затем удалите и заново добавьте бота в группу. Это нужно для распознавания кириллических команд: Telegram не считает их стандартными bot commands. Боту не нужны права администратора. После отключения privacy бот получает обычные сообщения; код обрабатывает только команды.
4. Из корня репозитория запустите `python3 bot.py`. Используется long polling; публичный сервер и входящий порт не нужны. Запускайте только один экземпляр на токен. Нужен HTTPS-доступ к `api.telegram.org`.
5. Одобрите группу в личных сообщениях боту. Затем в группе отправьте `/писюн`, повторите команду для проверки дневного ограничения, затем `/мой_писюн`, `/топ`, `/чат`.

Необязательные настройки:

- `DB_PATH`: путь SQLite, по умолчанию `data/game.sqlite3`. Сохраняйте базу между перезапусками; для резервного копирования используйте SQLite backup API или останавливайте бота и копируйте все файлы базы вместе с WAL.
- `GAME_TIMEZONE`: часовой пояс IANA, по умолчанию `Europe/Moscow`.

## Правила

Каждая пара «участник + беседа» начинает с 0 см. `/писюн` один раз за календарный день выбирает рост с вероятностью 70% или уменьшение с вероятностью 30%; величина изменения — от 1 до 10 см. Допускаются отрицательные значения. `/мой_писюн` показывает результат. `/топ` выводит 10 игроков, `/топ_все` — всех игравших в беседе (длинный список разбивается на сообщения). `/чат` суммирует их длины. `/ролл` выдаёт число 1–100 без дневного лимита.

Рейтинг включает только игравших, а не всех участников Telegram-группы. Бот не удаляет результат при выходе участника. Перенос рейтинга при миграции обычной группы в супергруппу пока не реализован. Общего рейтинга между беседами нет: его команда и правила в предоставленном описании отсутствуют.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Проверяются дневной лимит и московская полночь, разделение бесед, рейтинг, сумма, сохранение в SQLite, адресация команд, ролл и разбиение сообщений. Для проверки реального обмена с Telegram требуется токен и группа.

## Ввод команд

Команды вводятся вручную. Бот не показывает клавиатуру с кнопками и при каждом ответе скрывает ранее добавленную клавиатуру. После обновления отправьте `/help`, чтобы убрать старые кнопки.

При запуске бот удаляет ранее зарегистрированный общий список команд Telegram. Кириллические команды и латинские варианты `/grow`, `/mine`, `/top`, `/top_all`, `/chat`, `/roll`, `/help` продолжают работать при ручном вводе.


## Панель владельца и одобрение групп

Панель доступна только аккаунту из `OWNER_ID` и только в личном чате с ботом:

- `/admin` — справка по управлению.
- `/pending` — ожидающие одобрения заявки с ID чатов.
- `/chats` — все известные чаты и их статусы (`pending`, `approved`, `denied`).
- `/approve -1001234567890` — разрешить работу в указанном чате.
- `/deny -1001234567890` — запретить работу, в том числе отозвать ранее выданное разрешение.

При добавлении бота в группу сообщение о необходимой верификации появляется в самой беседе. Автоматические личные уведомления не отправляются ни владельцу беседы, ни владельцу бота. Владелец бота просматривает заявки через `/pending` и принимает решение командами `/approve ID` или `/deny ID`. Если событие добавления было пропущено, заявка создаётся при первой поддерживаемой команде. До одобрения игровые команды заблокированы. Администраторы групп не могут одобрять заявки. Telegram позволяет добавить бота без предварительного разрешения владельца: проверка ограничивает его работу уже после добавления. При запрете бот остаётся в группе, но не выполняет игровые команды.

Решения сохраняются в отдельной таблице SQLite и переживают перезапуск и повторное добавление бота. Старые результаты игроков сохраняются. Все существующие группы после обновления также требуют одобрения; миграция в супергруппу создаёт новый ID и требует нового разрешения. Заявки сохраняются независимо от доставки сообщения в беседу и доступны через `/pending`.

Опрос получает `message`, `my_chat_member` и `callback_query`. Ошибка обработки или отправки одного обновления записывается в журнал и не останавливает остальные чаты; автоматическая повторная доставка такого ответа пока не реализована. Игра могла уже сохранить результат до ошибки доставки.

Дополнительные тесты проверяют запрет игры до одобрения, права владельца, отсутствие автоматических личных уведомлений, отзыв разрешения, повторное добавление и сохранение решений после перезапуска. Реальный обмен с Telegram требует настроенных `BOT_TOKEN`, `OWNER_ID` и тестовой группы.


### Повторная заявка после отказа

Владелец или администратор беседы может отправить `/verify` (или `/verify@имя_бота`) в самой беседе. Права проверяются через Telegram `getChatMember`; для гарантированной проверки других участников Telegram требует, чтобы бот был администратором. При ошибке проверки заявка не меняется. Анонимному администратору нужно отправить команду от своего личного аккаунта.

После отказа `/verify` переводит единственную запись беседы из `denied` в `pending`. Пока заявка активна, повторная команда сообщает об ожидании решения и не создаёт дубликат. Для уже одобренной беседы новая заявка не создаётся. Обычные команды и повторное добавление бота не отменяют отказ. Все сообщения о повторной заявке появляются только в беседе, без автоматических личных уведомлений.
